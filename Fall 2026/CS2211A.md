
Operating system manages its hardware and resources such as ram, so the program doesn't need to.  It is essentially a resource manager, managing processes, assigning memory, files, and input and output.

CPU time sharing: different processes run using tiny amounts of time of a single core

Unix Philosophy:
- User helpful rather than friendly
- Protection from others but not necessarily themself
- Simple tools and building blocks that work well for one purpose
- By creating and using many tools together, works to complete complex tasks

Parts of the Unix OS:
- Utilities - tools and applications
- Shell: Interface between user and kernel
- Kernel: manages processes, resources, and hardware

Levels of programming languages:
- 1st: direct machine code binary
- 2st: assembly cide
- 3rd: high-level code (e.g. C)

A compiler is a program that transforms code from one level to another

An interpreter translates into byte code and executes it in real time, whereas with just a compiler, it creates and executable file

C is a language intended to be as powerful and efficient as assembly level languages. Structured to make code easy to read and write.

Account necessary for sharing of common resource (e.g. CPU time) and to keep secured resources separate

Files:
- Text files
	- printable characters
	- C source files to be compiled into byte
- Binary files
	- byte values
	- executable
- Directory files
	- list of references to inodes
		- inodes are data structures contained metadate for the file
- Link files
	- Hard links
		- links to data in another file
		- cannot link to directory
		- Deleting the data requires deleting the link
			- the link is essentially a copy (simplified)
	- Soft links 
		- links to data or directory
		- points to/references the target
	- All links change with the target, the difference between the hard and soft link is the ability to link to directory as well as hard link holding data independently to the target while the soft link points to it

Version Control: is a system and practice that allows you to revert to earlier versions of source code in the event that anything breaks
- Local: stored on machine
- Centralized: all changes stored on a central server that keeps the "canonical"  copy of the file, which only one user can have access to at a time
- Distributed each user has a copy of the full repository and tits history allowing for collaboration

Git:
- Working directory where the files are being worked on, for them to be tracked they need to be staged
- Staging area, snapshots of the file, before they enter the repo they must be committed
- Repository holds all the committed files and their records

Structures (Records): similar to a class with no methods
- Elements of structures are "members" which can be of different types
	- each member has a name that can be specified like variable names
		- have its own namespace scope
- the declarations of structures can use initializers like an array 
	- structName = {.member1 ='1', .member2="two",.member3=3}
		- designated with . and member name
		- can also just do position and compiler will infer like 
			- structName = {'1',"two",3}
- Can access member like structName.memberName like objects and their attributes
- structs can be copied, unlike arrays, but cannot be compared directly with ==
	- Arrays can be copied using structs
- structures can be named using typedef to define a name or with a structure tag
